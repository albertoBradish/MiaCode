# 基础排布

状态：2026-10-23，跨 token 一笔画及后续的 slide 尾点、共享启动拍、短扫与相邻键交互修复已完成 Release 主程序／启动器构建；`basic_hand_order_layout_spec` 与 `hand_order_tools_spec` 本轮聚焦测试通过。此前八分回弹、整圈扫等测试记录保留；主 GUI 仍待人工验收。基础排布与[自动手序](BASIC_AUTOMATIC_HAND_ORDER_SPEC_ZH.md)是两个独立命令。

工具栏提供直接可见的“基础排布”按钮，手序菜单和编辑器右键也可触发，默认快捷键为 `Ctrl+Alt+B`，沿用 ShortcutRegistry，可在首选项重新绑定。快捷键要求谱面编辑器焦点，快捷键录制期间不执行；没有选区时处理当前难度正文，有选区时仅处理完整选中的原生 token。同头多分支作为一个 token，部分选中的 token 保留。

## 位置与局部占手规则

- 普通外键 1–4 的默认手为右手，5–8 的默认手为左手；相邻短时动作可按两手最近位置调整。两手自然手位分别为左 E7、右 E3；空闲满 0.4 秒后按首选项中的固定回正速度逐渐靠近自然手位，距离越远所需时间越长。默认 3 场地半径/秒，可在 1–8 之间按 0.25 调整。Hold 的头与持续按压使用同一只手。
- Touch 和 Touch Hold 按解析所得传感区实际横坐标分配左右，不按编号机械划半。C 区和中轴传感区没有左右偏好，明确标为 `m`；这里的 `m` 表示任选一只手，不是未知或双手。
- 普通及链式 slide 的整条轨迹默认沿用原生运动起点手，即使后续跨屏也不预先产生换手；当轨迹占手会迫使随后音符跨手或造成同手占用冲突时，可将整条轨迹交给另一手。可见头按最近手位单独赋值；无头轨迹不新增可打头。Slide 从头时刻至终点占用轨迹手，结束后该手位于轨迹终点。
- 跨 token 的普通 slide 若前条尾点与后条起点为同键或相邻键，先按一笔画候选处理；折返和拐角允许，连续多条可串接。前条结束与后条轨迹启动的时间差须不超过两条各自 `240 / (BPM × 分音数)` 所得较短分音格的一半，并将此容差限制在 `1/180` 至 `0.15` 秒。轨迹优先继承前条手别，后条可打星头仍独立分手。若前条尾部与后条同键星头的名义时刻相距不超过 `27/180` 秒，则视为可能撞到启动拍，不采用该候选；其他已知持续物件占用同手时也不强制接续。这里只作基础排布的保守静态识别，不等于完整判定回放。复杂手工标注、多分支和选区外成员保持原有保护；更远空间跳跃及明显时间断开不由本规则认定。
- Slide 恰在下一颗相邻键 Tap／Hold 的头时刻结束时，轨迹手可从尾点接续；同键启动星头及远处音符仍视为占手，不能在尾点瞬间换位。若较长空白后的首个头仍位于尾点相邻键，且该键默认手与上一条轨迹手同侧，可重算它的旧简单标注，但不把整段空白视为物理连续滑动；中间已有别的头则不使用这条修复。
- Hold／Touch Hold 从头至终点占用其手。期间其他单音符由未占用的手击打；已有有效手序标注原文保持不变，但其持续占手会约束新音符。
- 同一原生 Each 组以及头时刻相差严格小于该处实际 1/64 音符时长的伪 Each，两颗独立音符必须各用一只手。同半屏时按横向相对位置分配；对侧双押若遗留 `8~r/2~l` 一类明显反向的简单旧标注，可重算成自然左右手。超过两颗同时音符或没有足够空闲手时，无法分配的 token 留在原文并计为不支持，不伪造同手双押。
- 同刻同键的 Tap 与可打 Slide 星头来自同一次按钮启动，头部手别必须一致；同键的多个可打星头也共享这一次头动作。旁边还有独立同刻音符时，它作为另一项押键分给另一手。无头 Slide 不提供可共享的启动星头。
- 同一可打星头同时发出两条终点不同、运动重叠的普通轨迹时，头仍可共用一次启动，分开的两条轨迹分别给两手。完整选中的简单旧双轨标注可重算；更复杂的人工区间继续保护。带启动拍的 Wifi 默认保留两个不同手的扇区，星头另按实际押键分手。
- 无锁手的同键 Tap 纵连须同时满足原生 `{16}` 或更密细分、相邻头间隔不超过 0.13 秒，才逐颗左右交替；至少三组、每组两颗同键并沿相邻键同向移动的绕手，组内保持同手、组间换手。`{8}` 或更慢的相邻两组同键回弹按谱面细分保持每组默认手，即使高 BPM 使实际间隔小于 0.13 秒，也不只凭秒数拆手；较慢的 `{16+}` 回弹同样可保持组内同手。
- 无锁手的高速整圈 Tap 扫若依次经过八个相邻键并回到起点，优先由起点手完成整圈，减少分页式逐半屏换手。终点若有与起点相对的双押，起点键仍归扫圈手，另一键归另一手；顺时针、逆时针和 `/` 两种书写顺序同样处理。至少五颗按原生 `{24}` 或更密分音格连续同向移动的短扫（如 `{32}8,7,6,5,4`）沿用起点手；`{32}` 或更密时，四颗连续同向 Tap 也可构成短扫。若紧邻前面的 Slide 占手，优先把其轨迹与短扫分给不同手；不能以分页制造瞬时跨场移动。
- 至少四颗按 `{16}` 或更密分音格在两个相邻键之间反复折返的 Tap（如 `(150){16}2,1,2,1`）逐颗左右交替；`A-B-A-C-A` 五连小型轴若 B、C 分居 A 两侧，也让中心三颗与外侧两颗分别由一手承担。两种交替相位按此前手位、占手和移动代价选择。它们与持续同向扫、同键纵连及每键双击的绕手分开识别。时间比较按该处 BPM 和分音格换算，不以固定秒数假设整首速度。
- Touch 的两个临位传感区若属于同一原生 Touchgroup，可同手触碰；相邻且先后间隔不超过 0.18 秒的 Touch 可同手轻扫。连续三颗以上相邻 E 区按该处 BPM 与分音格构成顺序扫时，优先沿起点手走完整段。E 区顺序扫的邻接与同刻 Touchgroup 分开判断：同时出现的相邻 E 区仍用两手。此例外仅适用于 Touch；外键 Tap／Hold 双押仍各用一手。
- 至少三颗连续、头位左右交替且轨迹时间重叠的普通星星，头与整条轨迹交替使用左右手。普通单轨迹不因此生成换手节点；若另有占手冲突，仍以未分配或局部约束结果处理。
- 未标注的 Wifi 生成显式 `split:`。原生扇区 0/1 对应外侧路径 0/2，比较两端点的横坐标，较左的扇区分配左手，另一扇区分配右手；即使两端都在同半屏，仍保留两只不同手。横坐标相同时以原生扇区顺序作固定裁决。基础排布不推断显式单手 Wifi。

标注格式遵守[手序语法契约](HAND_ORDER_ANNOTATION_SPEC_ZH.md)。上述明确识别出的节奏／临位模式可重算完整选中的简单 `~l/~r`，以及单分支 Slide 的 `~[head=l|r;track=0:l|r]` 旧标注。其他已有标注保持原文，包括 `~m`、复杂换手、Wifi 旧整体、显式 Split/Single 和已有非法标注；选区外标注不重算。非法标注会报告诊断，不能被基础排布悄悄修写。无标注数字簇按原 Each 关系展开为独立标注音符。

## 编辑事务与边界

本命令使用生产解析器的 UTF-16 源 token 范围、原生几何和已有手序序列化器。原生语法错误阻止本次写入；输出重新进行严格解析。时间、几何、音符数量、修饰和 Each 保持不变，只增加或调整手序标注。

一次执行通过现有 Scintilla 桥提交一个编辑事务，一次撤销恢复完整操作。空选区处理当前难度后保留原光标的对应位置；有选区时沿用现有选区事务。重复执行已正确的标注不创建空撤销。反馈分别列出改写、保护已有标注、部分 token、不支持及诊断数量，并说明没有动作可行性回放。

基础排布的局部占手仅使用谱面时间、标注和位置；不运行完整判定回放、束搜索或预算计算，也不把左右分配解释为人体可玩性、官方判定或置信保证。无色 `m` 仍表示任选一手，不能据此推断其持续占手。后续自动算法可使用同一位置规则作为软偏好，再根据上下文判断实际动作和换手。简单旧标注在明确模式中会重算，因此刻意指定的简单 `~l/~r` 也可能被改写；复杂区间和选区外标注继续保护。

基础排布写入的是正常持久标注，自动手序默认会保留。若希望继续自动优化，选取待优化的完整音符，运行“基础自动手序”，并在结果面板勾选“重算选区已有手序”后重新分析；没有选区时对应当前难度范围。检查预览后再应用。基础排布不会自动开启该选项或更改已有标注的保护偏好；选区外标注继续受保护。

## 验收入口

- `basic_hand_order_layout_spec`：1–8/持续音符、跨屏及链式 slide、跨 token 同键／相邻键一笔画、BPM／分音格与容差上下限、无头与三段接续、撞启动星头拒绝、Slide 尾点后的首个相邻 Hold 与较长空白后的旧标注修复、同键 Tap／星头及旁边独立押键、Touch 中轴、Wifi 双扇区、同半屏 Each／伪 Each、Slide／Hold 占手、快纵连、绕手、整圈扫／短扫及末尾双押、80／222／240 BPM 八分回弹与同 BPM 十六分对照、临位 Touchgroup／轻扫、旧标注交替星星修复、复杂标注及选区保护、UTF-16/CRLF、原生投影和幂等性。
- `hand_order_tools_spec`：真实 Controller 文本事务、Scintilla 一次撤销、空选区当前难度、可见工具栏按钮和实际点击。
- `qml_shortcut_binding_spec`、`shortcut_preference_persistence_spec`：独立默认绑定、实际 QML 触发、空选区、重绑、录制/焦点守卫及重建注册表后的持久化。

当前验证只使用工作区合成资料；主 GUI 和真实谱面结果另行记录，不沿用旧版本通过记录推定本轮新增按钮已经验收。
