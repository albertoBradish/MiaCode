# 自动 Sticking（实验性，算法 v12）

算法 v12 增加两类连续动作：可打星头后，同键以舒适间隔连续击打三次时，轨迹优先交给另一手，按键手留在该键；两组三键同向扫迅速重复且需要从末键跳回起键时，优先让第二组换另一手。双押阶梯中的慢速同键接续贯穿下一组双押；孤立单键不会据此强制下一组手别。相邻 `4/5` 等键位的交叉双押允许结合前文占手判断，距离较远的反向交叉仍受硬约束。这些偏好仍需经过实际输入完整回放。

用户提供的《プリズム△▽リズム》正确标注副本用于本地对齐，未收入仓库；对该谱第 5 难度的 568 个原生音符，v0.2.7 基线与范文相差 123 处，本轮默认参数相差 69 处。这里的“相差”是手序标签逐音符对照，不代表剩余 69 处都存在判定错误，也不把无差异视为人体可玩性证明。以下 v11 至 v4 内容保留为历史实现记录。

算法 v11 的按键扫键候选由实际相邻间隔决定：以音符处 BPM 和 `{N}` 换算一个分音格，连续相邻键须落在该格的 ±10% 内，且相邻间隔不超过 `15 ÷ 扫键阈值` 秒。阈值是等效 16 分 BPM 的整数，首选项可设 60–600，默认 160；160 对应 BPM 160 的 16 分，300 对应 BPM 150 的 32 分。两颗同侧键可连扫；跨左右区域的两颗键要求另一手正被持续配置占用；三颗及更长同向键列按连贯路径考虑，另一手空闲的跨中线四键短扫仍允许分成两段。ABAB 交互、`A-B-A-C-A` 小轴、快速纵连和伪同刻仍由各自规则处理。双押作为扫键起点时，另一手的同时击打阻止四颗短扫中途分页；高速双押的两条路径可分别沿 `4→5` 与 `8→1` 接续，不按屏幕左右强制换色。

基础排布为星头、轨迹分别分手，并在后续轨迹入场时检查已知持续轨迹的占手交叠；已识别的一笔画接续与重合轨迹可共享移动。双押后的延迟同键接续保留原击打手，但仍作为新的击打。自动求解继承这些短扫和接续的偏好，所给候选仍须通过实际输入的完整回放；基础排布本身不提供可玩性证明。

“未决音符使用默认手序补色”默认关闭；两手均不可安全分配、搜索预算不足等未决音符不新增手序色。主动勾选后，基础排布可按默认侧补色并显示未验证数量，自动结果以“默认手序补色，未验证”展示，`fullReplayVerified=false`、置信证据不足；仅高置信应用时禁用该补色。已写入谱面的注释不会因为关闭复选框自动删除，后续重算仍须显式启用“重算已有 Sticking”。以下 v7 至 v4 内容是历史实现与验收记录。

算法 v7 把基础排布的手别和一笔画接续关系作为自动搜索的起点偏好，并在正常 BPM 范围的同刻对侧双押中排除明显反向跨手。对因工作预算耗尽而未获完整回放解的完整目标 token，若基础排布已有合法标注，结果可提供“基础排布补全，未验证”的低置信候选；高置信模式不应用这些候选。原生错误、实际候选不可行、人工复杂锁和基础排布本身也无法分配的音符不会伪造标注。以下 v6 描述为历史实现记录。

`{32}` 或更密的四颗连续同向按键作为一个快速扫求解单元；这包含 Slide 起手后立刻出现的短扫。局部求解同时评估轨迹占手与整段扫键，不因逐颗滚动搜索而把扫键分页。

算法 v6 对正常高速纵连添加连续同手击打代价，并识别 `A-B-A-C-A` 五连小型轴。连续同向扫键的中途分页以及按时序扫过相邻 E 区的中途换手，作为独立的手法断点优先比较；其候选仍须通过完整判定回放。E 区顺序扫被纳入同一滚动求解单元，同时出现的相邻 E 区仍按独立 Touch 判定，不借用同刻 Touchgroup 规则。以下 v5 描述为历史实现记录。

同刻同键可打双星若形成同时运动且路径明显分离的两条普通轨迹，自动排序优先让两条轨迹从起点分归两手；共同启动拍只消耗一次按键。未锁定的带头 Wifi 优先使用双掌扇区，有限候选中双掌不可行时仍可尝试通过完整回放的单掌方案。已有人工锁定的单掌 Wifi 不由此偏好改写。

算法 v5 增加四颗及以上相邻键 ABAB 十六分及更密交互的同手连续击打软代价；回正位置改为左 E7、右 E3，空闲 0.4 秒后按首选项速度向自然位置移动。默认 3 场地半径/秒，范围 1–8；它是归一化场地单位中的可调启发值，尚未按实体屏幕距离校准。已有标注默认仍受保护，重算已有手序须启用对应选项。下文所述 v4 验收是历史记录，不代表 v5 的验证结果。

状态：2026-10-22，v4 已经主代理独立验收。完整 MiaCode / MiaCodeLauncher Release 构建成功，23/23 项关联 CTest 通过（11.97 秒）。普通局部推断、默认 6/3 手位、基础手别共享、滚动状态传递、原生全目标输入竞争审计和预算诊断已通过本页列出的合成与授权副本回归。

本轮未启动主 GUI、未使用 Computer Use。真实输入仅为用户明确授权并复制到当前工作区的指定谱面测试副本，未读取原谱目录的其他文件，未改写原谱；该副本不进入源码提交或发布包。通过范围限于固定社区 profile、有限动作模板和默认预算：较大难度仍有明确未决，不能称为全谱已解或人体可玩性证明。v3 的历史 19 项验收和覆盖保留在后文，不能代替本轮 v4 结果。

## 输入、选择与应用

沿用“基础自动手序（实验性）”、默认 Ctrl+Alt+H 与 ShortcutRegistry。无选区分析当前难度；有选区只写完整选中的 token。默认保留全部已有标注原文，包括复杂区间和 `m`；“重算选区已有手序”仅解锁完整目标 token，选区外标注继续约束实际动作。部分 token 只读。

输入通道偏好提供外键优先、内屏优先和混合。外键 1…8 与屏幕 A/B/C/D/E 是独立通道；外键击打不会自动产生 A 区覆盖。外键与对应屏幕的同手共享使用有限可达模板，随后回放两条实际通道；其他手加入持续 ON 区域不会制造新 DOWN。实际路径先只压缩与时间线性插值相同的点（仅浮点舍入容差），保留速度变化、转折和端点，完整回放必须与压缩前一致。纯普通按键在首选通道的名义时刻保留增量搜索路径，发生通道冲突、共享或持续动作时联合搜索实际外键/内屏候选。

结果先预览，再以一次编辑事务写入。每行“定位”在当前请求身份仍有效时选中原文 token；编辑、切谱或重开文档后拒绝旧坐标。可选择全部可写建议或仅高置信建议。后者按完整 token 和真实硬依赖单元闭合：同刻、Touchgroup、同手实际共享或因果关联的单元中有可写低置信、未决或证据不足成员，就不从该单元拼接零散标签。普通软邻居和纯异手持续时间交叠不因此合成同一写回单元。未知和混合责任不以 `m` 补齐。参数、文本、revision、文档代次、难度、时序元数据或请求 sequence 变化都会让旧结果失效。

## 真实动作与完整回放

`HandOrderFullReplay` 只消费调用方传入的真实动作，不由 marker 自动制造输入、不把 `onSlide` 当判定证据。每个输入包括实际手、外键通道或屏幕中心连续路径、接触区间与有限接触半径。算法默认普通半径 15/240，Wifi 掌形为原生有限 50/240；不存在覆盖整屏的圆。几何以原生参考半径 240 归一化。

所有覆盖者的并集确定传感区 ON。总状态 OFF→ON 才有可消费 DOWN；一手离开但另一手仍覆盖、换色、换手重叠与来源变化均不会产生额外击打。屏幕路径与各 pad 圆形区域解析求交后投影到 180 Hz 计算网格；长休息或持续 ON 不需要从零铺满每个 tick。计算网格不是官方硬件帧率的断言。

完整回放逐 marker 返回头判定、轨迹各区域命中/跳区、链段边界、Wifi 三队列进度、实际判定时刻与余量、因果来源和 Hold 有效持续比例。它检查普通按键、Touch/Touchgroup、Hold/Touch Hold、普通/原生链式 Slide 与 Wifi。目标默认社区参考的 Critical 质量；Bad/Miss 仍返回审计结果，但不会使候选通过。回放失败只能返回“有限候选中未找到满足目标的方案”，不能描述为已证明人体不可打。

`HandOrderJudge` 的 Touch 子回放只用于提出独立触碰、覆盖和组联动候选。终态以完整回放的判定与因果为权威，再检查人工手别约束和可编码性。因此按键/Touch 争用同一输入时，预览不能继续展示另一套局部责任。Hold 的单手责任使用 `singleHandCompletionMask`：保留联合回放真正消费头事件的手资格，在同一事件流分别积分左/右手独立的有效 body。另一手冗余刷过不会误判成必需接手；真正左右互补维持却没有任一手独立完成时，单色 Hold 必须拒绝。审计的全部贡献者集合仍完整保留。

## 版本化判定 profile

自动算法 `basicAlgorithmVersion=12`，参数判定修订 `basicJudgeProfileRevision=2`；独立完整回放首次 profile 为 `fullReplayProfileRevision=1`。参考固定提交的 MaiMuriDX `0ebab7ff6853a159ef6af76d9e3c43b23157bb5e` 开发笔记与本地原生 slide 判定队列。该社区来源描述日版 Buddies / 国服舞萌 DX 2024 的范围，不等于所有框体或官方内部规格。

- Tap Critical 窗口为 ±3/180 秒，可接受窗口 ±27/180 秒；Touch 对应 ±27/180 秒。
- Slide 使用原生区域序列、短轨保护区域、长轨跳区、原生链段衔接与最终判定窗；可接受尾窗为 108/180 秒。不会把本地旧 Muri 的 24 小时宽限套入新 profile。单段 V/L 形按参考的 `is_l` / `is_special_l` 保护 0 基索引 1（特殊 L 另保护索引 3）。多原生段链按拼接队列总区域数执行普通短/长轨跳区；V 起手链不继承单独 V 的专用保护。这是固定社区参考的链式行为，不推定为官方所有版本规则，也不借此修改旧 Muri 的独立行为。
- Wifi 默认采用 DX 参考 `wifiNeedC=false`；独立回放可显式选旧 C 释放规则，三条队列仍由真实 pad 覆盖分别推进。
- Hold 有效 body 忽略头 6/60 秒、尾 12/60 秒；Touch Hold 忽略头 15/60 秒、尾 12/60 秒。连续 OFF 达 3/60 秒才追溯扣除，短 OFF 忽略；Hold body 允许对应外键/A 的覆盖并集。默认 Critical 要求有效 body 完整，生成器仍可保守保持完整物理持续动作。
- EX、短 Hold 和头 Miss/body 命中的社区行为返回对应审计等级；本轮没有声称重现每个官方得分细分或版本变体。

## Wifi 表达与候选

旧 `~l/~r/~m` 及旧整体 track 序列保留原来的文件/显示语义。新的 `track=split:0:l&0:r`（多分支沿 `branchN`）保存原生两侧的独立序列；`track=single:0:l` 明确整条 Wifi 由同一只手完成。`single:0:m` 只允许整条任选一只真实手，不能在区间内换手，`m` 也不表示两手。

双掌候选使用参考数据的 `di_real_path_samples` 实手路线，并依据末端相对原生外侧轨迹映射稳定扇区；不会把三条美术星轨直接当成两手动作。两手真实占用分别计入，中央判定队列由两实际接触圆共同覆盖的结果决定。单手候选是一条连续路线，按原生三队列区域交替扫动，必须独自通过全部判定；不能把两条同时位于不同位置的手路统一改色冒充单手。

生成结果实际序列化为 split/single 语法并严格复读；再次分析会把这些手序作为人工锁。手序编辑、镜像、旋转、预览与视频 snapshot 的契约见 `HAND_ORDER_ANNOTATION_SPEC_ZH.md`。单手扫动的压力与特殊动作条件必须显示，颜色不能充当可玩性保证。

## 复杂共享、换手与评分

同手逻辑路径在重合、部分重合、分叉、汇合和连续衔接时，先共同构造一条实际中心路径。联合几何使用完整有限集合检查，不能由 A 接近 B、B 接近 C 推导三者可共享。当前路径提案偏移上限 0.20 场地单位，外键/内屏同手可达上限 0.32；这些是显式实验模板，不会扩大实际接触半径。合成后的真实中心再次通过全部独立判定队列，不能因几何接近直接宣布共享完成。

轨迹评分对每手物理并集积分，重合逻辑轨迹不重复收费。持续轨迹的移动代价为 `d + 0.1 v²dt`，出张按持续时间积分；等价细分不降低运动成本。普通按键另采用下述局部软适配费用，预览中的代价不应解释为整曲累计物理距离。接手重叠为 2/180 秒；普通自动轨迹最多枚举 3 次接手，稳定区间至少 0.1 秒，候选点有界。重合轨迹的同一真实接手按时刻、位置与前后手聚合，采用最大边际罚分一次收费。

第二次及以上接手须将该轨迹限制为至多一次并公平重优化。反事实保留当前所有强制手别，包括正在验证的 Touch 或轨迹区间。受限候选更好就替换完整解；否则只有明显压力改善或未剪枝离散搜索确实未找到受限候选才准入。人体速度为压力指标，未经校准不作为绝对人体不可达证明。

名义同刻任务联合扩展，外键短按可在目标 Critical 窗内选择有界时刻；普通按键不会用 Touch 的宽窗降判换顺手。等候期不占用打头手；先行纳入的轨迹可覆盖同刻头/周边按键，覆盖仍需真实 DOWN 与完整回放通过。

## 反事实、置信与压力

在全请求组件预算内，对普通按压头、Touch 责任手、普通/链式轨迹输出区间及 Wifi 两扇区执行当前滚动单元反事实。已承诺历史动作保持固定；强制另一只手后重算当前窗尚未承诺的其他手别、通道、时刻、共享和换手准入；不从若干不相容方案拼出独立颜色。发现反手更好时替换整套方案，再重算证据；有限反复仍不稳定时未决。束剪枝前以前后文已锁 Hold 的同一外键/A 有限模板前视引导排序；前视宽度 4，发生剪枝明确记录。它只是候选排序与可达模板检查，不是完整未来判定证明，终态仍重新计算真实动作评分并完整回放。

证据记录是否搜索、是否找到、是否剪枝/预算不足、另一只手、区间运动进度，以及有符号风险档差、峰值档差与总成本差。启发分为 `1-exp(-separation/1.5)`，separation 为正向成本差与风险档差的明确加权和；非普通单键模型另计峰值档差。反事实至少搜索一次换手，仍未找到时扩大至三次或明确预算不足；不能把常手阶段反手失败直接算作完整无反例。仅未剪枝且证据完整的候选中未找到反手时，启发值才可为 0.95。剪枝证据最多 0.74，工作/组件预算不足最多 0.39，缺证据不产生高分。一个 token 取所有生成组件的最低分。峰值速度达 12 场地半径/秒时，动作被标为极高压力，可靠性启发分最高 0.39，不进入高置信自动应用；这是实验应用策略，不是人体硬上限。

界面显示 0–100 启发分及高/中/低/证据不足；高阈值 0.8、中阈值 0.4。它不是统计正确率、模型准确率或人体可玩性概率。置信和压力分开：高置信也可能需要快速、交叉或特殊扫动；当前核心的真实峰值速度与局部适配代价独立显示。

## 上下文、预算与未决

普通软邻域默认前 1 / 后 2 个时序组，不传递续接；关联同时按 `exp(-秒数/0.35) × 0.5^中间音符数` 衰减，软时域为 `max(0.35, contextSeconds)`。context 为 0 仍保留 0.35 秒内的最小局部邻域，不把长休息另一侧的对象强行拉入。同 token、同刻全部对象、Touchgroup 保持原子；持续输入、有效头/体判定、明确手序锁和实际输入复用属于硬约束，不能按软邻域数量裁掉。即将发出的 DOWN 若可被更早尚处于可判窗的同通道 head 消费，还会导入这些真实消费者作为只读硬上下文；该消费闭包仍逐窗求解，不能重新合成一个全曲搜索束。

默认基准为左手左半屏、右手右半屏，初始位置分别为原生 6 / 3 区；Slide 的基础手别按真实运动起点，跨屏本身不先拆手。每窗保留两手实际末位置与时刻、仍活动接触的原始 start/end、已消费星头来源和固定真实中心。历史输入参与回放而不在新窗重复打击/收费；后窗只能适应已承诺动作。无论本窗是否生成标签，原生有效判定对象仍参与最终回放中的输入竞争；只检查实际生成候选的达标与责任，不把未决目标变成自动输入。选区外全部只读。

主轨迹先尝试不换手的基础方案，无解再扩一次、最后三次；只有极高压力时才用有限可选份额提前尝试一次换手，失败仍保留已验证常手方案。候选按名义时刻首选通道、名义时刻其他通道、最后 Critical 时间偏移分层扩展。普通主搜索先用束宽 8，无解再回退配置宽度（默认 64）；三成员及以上 Touchgroup 的责任比较、反事实和少换手受限基线直接用配置宽度，不能让窄束吞掉已存在的近优异手责任。主候选的实际裁剪也进入反事实 limited 标记，不能据此产生伪高分。普通扫键的真实速度继续作为压力显示；软适配中速度费用系数为 0.01，其他动作仍为 0.1，普通侧身费用为 `2 × 跨过身体中线的距离`。普通反事实采用相同软成本尺度，不使用不参与普通排序的峰值档差抬高置信；实际峰值审计独立保留。

默认束宽 64、单窗最多 512 决策/目标、全请求反事实组件预算 64、共享搜索/评分/回放总预算 3000 万工作单位。普通物件多不等于单一搜索块；每窗获得有界公平工作份额，失败后继续其他独立窗口。可选反事实合计最多使用总预算的三分之一，还需先扣除按纳入物件数和剩余窗口数估计的保守主解工作地板；不足时直接记证据不足，不能挤掉原本能完成的普通主解。另预留至多十分之一预算用于最终合并回放。独立完整回放另有有限事件表上限，所有路径持续检查取消。某窗口主搜索耗尽时，该窗无候选可写；已通过完整回放的候选若只是可选证据耗尽，可保留待复核且标为证据不足，不能高置信应用。

Mine、未知原生几何、Hold 中途移交、超出有限模板/路径/工作预算的方案仍明确返回限制或未决；这些边界不替代本轮的 Wifi、共享动作和完整回放核心实现。本算法不调用原生 Slide 结构拆分。官方版本矩阵、真实谱面专家答案、三维身体碰撞/疲劳与主 GUI 仍须独立验证。
