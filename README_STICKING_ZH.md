# MiaCode Sticking 2.0.0-alpha（Windows x64）

将整个压缩包解压到**可写目录**，双击根目录的 `MiaCode.exe` 启动。请保留 `app/`、`assets/` 和 `StickingPackage.marker`；只复制 exe 无法运行。

打开项目的 `maidata.txt` 时，Sticking 会在同一目录创建原始字节副本 `maidata_sticking.txt`，并将后者作为当前编辑和普通保存目标。若副本已存在，则直接继续编辑副本，绝不自动覆盖。原 `maidata.txt` 不会因普通保存改变；明确使用“另存为”选择其他路径仍按所选路径保存。该目录需要可写权限，副本创建失败时不会打开原文件供编辑。

本版本支持 `~l`（左手蓝）、`~r`（右手红）、`~m`（左右任选灰白）的手序标注；`m` 不表示未知或双手。Slide 可按运动进度换手；Wifi 可选择两扇区独立标注，或整条轨迹同一只手的显式单手模式。显式单手会显示圈“1”，这个标识不保证实际手法可打。内置 SD/DX 皮肤使用从原美术生成的染色素材。未标注的音符及关闭手序显示后的画面使用原皮肤；视频导出可选择跟随预览、原谱或手序模式。

工具栏“Sticking”、调整菜单及编辑器右键提供以下入口。使用编辑快捷键前先点击谱面正文；可在首选项的快捷键页重新绑定。

| 默认快捷键 | 功能 |
| --- | --- |
| Ctrl+Alt+B | 基础排布：有选区时处理完整选中音符，无选区时处理当前难度；识别纵连、绕手、临位 Touch 和交替星星，简单旧标注可在明确模式下修正。 |
| Ctrl+Alt+H | 基础自动 Sticking（实验性）：先分析并预览，再按所选策略应用；已有标注默认保留，未决结果不会用 `m` 填满。 |
| Ctrl+Alt+1 / 2 / 3 | 完整选中音符设为左手 / 右手 / 任选；已有 Wifi 显式模式和区间边界保留。 |
| Ctrl+Alt+4 | 拆分 Sticking 区间：增加标注节点并打开区间编辑器，保留原生链式 slide 结构；Wifi 可在此选择双扇区或显式单手。 |
| Ctrl+Alt+5 | 拆成独立 slide：先预览原文和转换结果，再确认整批应用；会增加独立原生轨迹及判定边界。 |

工具栏也有直接可点的“基础排布”按钮。1–4 默认右手、5–8 默认左手；同刻 Each 和间隔短于实际 1/64 音符时值的伪 Each 通常分给两手。无锁手的高速 `{16}` 或更密同键纵连逐颗交替，成对绕手组内同手、组间换手；`{8}` 回弹不因高 BPM 使秒数变短而被误拆。高速整圈扫优先由一只手走完整圈，末尾相对键双押由另一手接另一键。只有同组相邻 Touch 可同手多触，相邻短 Touch 也可同手轻扫，外键双押仍分两手。Slide、Hold 和 Touch Hold 的持续动作占手，左右交替的重叠星星会修正头与整条轨迹的手别；未标注 Wifi 使用左右双扇区。明确模式可重算简单旧标注，复杂手工标注和选区外标注保持原文。基础排布不做可玩性回放；随后使用实验性自动手序时，仍需在其面板勾选“重算选区已有手序”并重新分析。

本轮增强了五连小型轴、高速长纵连、Hold 后紧接的单手扫键、A/D/E 圈及跨圈顺序 Touch 扫，以及从同一星头同时展开的双轨分手。不同键的 Hold 在前条名义尾部恰接后条头部时换手，不把可判定的提前松手当作瞬时位移。自动推断优先保持带头 Wifi 的双手扇区；单手候选仍需通过完整判定回放，结果请在应用前复核。

自动 Sticking 先参考基础排布的手别与一笔画接续，再用动作搜索和完整回放调整。若复杂局部因工作量限制没搜出经验证方案，基础排布已有的合法手别可作为“未验证补全”供人工复核；它不会进入“仅高置信”应用。基础排布也无法确定或完整回放已发现不可行的内容保持未决，不会编造手别。明显反向的同刻对侧双押会修正简单旧标注。

偏好设置的编辑器页提供“综合、硬抗、分页、拆谱”四种风格预设，也可手动调整单手参考手速、位移速度、体力、恢复、打法和自然侧姿态，随后显示为“自定义”。综合默认参考手速为 6.5 次/秒，位移速度为 7 场地半径/秒；旧测试安装已保存的个人数值会保留，选择“综合”即可应用新预设。搜索预算可选低 5000 万、中 3 亿、高 6 亿或最高 10 亿的自定义工作量；它限制搜索工作，不是内存或 CPU 占用上限。未决音符默认按基础排布补色并明确标为“未验证”，不会进入“仅高置信”应用。玩家参数是工程参考值，不是人体测量或绝对速度限制；修改后需要重新分析。分析面板显示局部候选的击打峰值和负荷估计，短 Touch 装饰的瞬时峰值不能当作持续连打要求。

连续绕手中的有意交叉双押会结合前后圆周路径判断，不再一律当作孤立反手错误。跨侧短扫可由两手连续分段，完整圆周与被持续动作占手时仍优先保持连贯。HOLD 提供由现有完整回放验证的释放候选；不会改写原音符时长或放宽判定规则。实验性分析仍需保留复杂配置的人工精校。

算法 v15 允许短时爆发，持续超速仍积累负荷；扫尾接 HOLD 保持三扫连贯。浅单键出张的扣分降低，同头分支的左右空间次序、持续轨迹之间的前臂交叉和一笔画起滑前的反向折返优先检查；首组一笔画也会带入后续动作。短 HOLD 和 TOUCH HOLD 按各自有效按压段处理，EX、BREAK 不解除持续占手。上述动作评分仍是启发式，完整回放通过也需要人工复核。

算法 v16 进一步区分固定占手旁的短暂跨手和连续动作互相穿插，避免重合逻辑轨迹重复计费；长 HOLD 的持续出张按必需按压段时长评分，同侧中速四连扫也保持连贯。保留 v15 的同头分支与一笔画约束，既有人工手法仍可能有不同的可行选择。

两种拆分的作用不同。手序区间拆分只编辑额外标注；独立 slide 拆分会改变原生对象，即使运动形状和起止时间保持，计分、Each、判定、出现与消失、音效及 Muri 也可能改变。应用前检查预览，应用后可用一次撤销恢复。

配置、缓存、会话、日志保存在解压目录的 `runtime/`，默认导出目录为 `exports/`。它不读取或迁移正式版 MiaCode 的偏好、自动恢复内容和谱面。将整个解压目录移走时，这些数据也会一同移动；建议自行备份在此版本创建的谱面。

发布包初始 `runtime/` 为空。请按 [acceptance/MANUAL_CHECKLIST_ZH.md](acceptance/MANUAL_CHECKLIST_ZH.md) 使用随包合成 `maidata.txt` 做人工验收；建议先复制合成文件到新位置，再测试保存和重开。清单复选框留给操作者，尚未勾选的主 GUI 项目不能视为已通过。不需要打开真实谱面或复制正式版配置。

如需命令行，可用 `powershell.exe -NoProfile -File .\Start_Sticking.ps1 <参数>` 或 PowerShell 7 的 `pwsh` 运行同一脚本；它会为子进程设置包内运行根并转发参数。如果本机禁止 PowerShell 脚本，使用根目录的 `MiaCode.exe` 启动器即可，无需修改系统策略。不要直接运行 `app/MiaCode.exe`。打包时会在本文末尾附加该构建的版本、渠道和 Git 身份。

本包仍为 alpha。合成谱面的解析、自动手序及编辑事务、真实离屏控件和 QSG/导出回归已通过；主 GUI 人工视觉与交互、真实谱面批量导出和跨平台行为仍待验收。自动手序采用有限动作模型及社区参考规则，结果需要复核，不是官方规则或可玩性保证。Windows 可执行文件未附代码签名。
